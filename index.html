DAY 01

What is LangChain?

LangChain is a framework for building LLM-powered applications using reusable components such as prompts, models, parsers, tools, and retrieval systems.

RAW API

Direct Model Interaction

With a raw API call, the application directly communicates with the model provider and manually handles the request and response.

Your Code ↓ API Request ↓ LLM ↓ Response
LANGCHAIN

Reusable Components

LangChain allows different components to be connected into reusable workflows called chains.

Prompt ↓ LLM ↓ Parser ↓ Result

What is a Chain?

A chain is a predefined sequence of components where the output of one component is passed to the next.

PromptTemplate → LLM → Output Parser

LangChain Expression Language (LCEL) uses the | operator to compose these components.

DAY 02

Prompt Templates & Output Parsers

Prompt templates make instructions reusable, while output parsers help applications handle model responses in predictable formats.

01

Prompt Template

A reusable prompt containing placeholders that can be filled with different values.

Explain {topic} in simple words.

topic = "LangChain"
→ Explain LangChain in simple words.

02

Output Parser

A parser helps convert or handle the model's output in a format that an application can work with.

LLM → Parser → Usable Output

STRUCTURED OUTPUT

From free-form text to predictable data

Applications often need specific fields instead of a paragraph. Structured output makes the result easier for software to process. 

{
  "name": "Python",
  "difficulty": "Beginner",
  "uses": [
    "Web Development",
    "Automation",
    "Data Science"
  ]
}

StrOutputParser

Used when the application needs the model response as a clean string.

JsonOutputParser

Used when the application needs structured JSON-style output.

Pydantic

Defines and validates the expected structure and data types.

DAY 03

Memory & Tool Calling

AI applications can maintain relevant conversation context and use external tools to perform tasks or access information.

MEMORY

Context across conversations

Memory is an application-level mechanism for storing and supplying relevant previous information to the model.

User Message ↓ Conversation History ↓ LLM ↓ Context-aware Response

The LLM does not automatically have permanent memory. The application manages and provides relevant context.

TOOL CALLING

Giving the LLM external capabilities

Tools allow an AI application to interact with services such as calculators, databases, APIs, search systems, and other functions.

Calculator Database Weather API Search

TOOL CALLING FLOW

The LLM requests; the application executes.

LLM → Tool Request → Application → Tool → Result → LLM

What is LangGraph?

LangGraph is a framework for building stateful, graph-based workflows and agent systems with nodes, edges, state, branching, and loops.

START
↓
Analyze Request
YES
Call Tool
NO
Respond
01

Nodes

Individual steps or functions that perform work.

02

Edges

Connections that determine what happens next.

03

State

Shared information carried and updated through the workflow.

04

Conditional Edges

Routes execution based on a condition or state.

CHAIN

Fixed execution path

A → B → C → D

The sequence is predefined and execution follows the same basic path.

LANGGRAPH

Multiple possible paths

A → B ↙ ↘ C / D

The workflow and possible routes are defined, but the path can be selected dynamically at runtime.

↓
FINAL RESULT

WHY AN ORCHESTRATOR?

One system, multiple specialized responsibilities.

  • Breaks complex tasks into manageable responsibilities.
  • Routes work to the appropriate specialized agent.
  • Coordinates information between agents.
  • Works naturally with stateful workflows.
  • Makes multi-agent systems easier to extend.
Important distinction:

LangGraph is a framework for building graph-based workflows. An orchestrator is an architectural role responsible for coordinating agents or tasks.
